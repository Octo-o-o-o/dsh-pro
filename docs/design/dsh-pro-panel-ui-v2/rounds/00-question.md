# dsh-pro panel ui v2

## 研究问题

为 ChatGPT Pro Research 与 GPT-Image Design 设计：点击侧栏进入后的主题列表，以及点击主题后的详情；同一套外壳下两种内容侧重，并映射现有字段、状态与动作。

## 成功判据

- 3 张 1722×997 级桌面方向图，每张同时给出列表 + 详情，并标出 Research 与 Design 的内容差异
- 列表在 240–320px 可读：状态、两行标题、类型、轮次、更新时间、产物/卡住标记齐全；含选中、悬停、空态、加载态
- 详情有清晰的标题/状态/主操作/轮次/产物层级；Research 的 final.md 与轮次表、Design 的图片画廊与 demo 各有明确重点
- 单文件 HTML demo 可离线在 iframe 打开，能切换 Research/Design、列表/详情、浅色/深色，并用真实字段与示例数据
- 设计只使用现有 /topics、/topic 字段与状态机动作，不新增后端接口；浅色/深色均与 DSH 中性 UI 协调
- 提供一份可执行的落地映射：信息块→字段、主/次/危险操作→action，并说明哪些需要新增前端状态

## 任务

你在为一个 DeepSeek Harness（DSH）桌面 Web GUI 里的两个本地插件做「主题列表 + 主题详情」重设计。两个插件共用同一个客户端面板外壳，源码在 packages/research/client/panel.tsx，设计插件通过 designMode 切换内容。

【产品与用户】
- ChatGPT Pro Research：无人值守多轮调研。用户发起主题，后台跑轮次，详情看每轮问题/裁决/附件/回答、最终 final.md，并做接受、继续、恢复、取消、请原会话判断等决策。
- GPT-Image Design：用同一个网页会话或 OpenAI 兼容生图 API 出设计图/HTML demo。详情看每轮方向图、全部图片、前端 demo、代码与文件，并做接受、重新生成、继续一轮（可指定 1–6 个方向）、取消等。
- 共同点：主题是长任务，不是聊天。用户点 DSH 左侧栏的插件后先看到主题列表；点一个主题进入详情。列表负责扫描/定位，详情负责判断下一步 + 看产物。

【材料说明】
- current-ui.pdf：4 页现状材料，含两张真实运行截图、现状问题、状态色与动作摘要。第 2 页是 Pro Research 列表+详情，第 3 页是 GPT-Image Design 列表+详情。
- ui-inventory.md：完整字段、状态、动作、两插件差异、当前视觉问题清单。
- panel.tsx：两个插件共用的现有客户端实现；设计要能映射到这份 createElement 结构。

【现状与要解决的问题】
- 现状：固定 240px 列表，只有状态点 + 单行标题 + “状态 · n/cap 轮”；长标题全部截断，没有类型、更新时间、产物数、卡住标记、搜索/筛选/分组。详情首屏被元信息、路径、自检/登录按钮占据，主操作不突出；7 列轮次表大量留白；设计插件的图片网格和 420px demo iframe 直接铺在详情里。两个插件看起来几乎一样。
- 目标：列表 240–320px 可扫读；详情 900–1600px 有清晰层级；两个插件共用外壳但内容各有侧重。

【本次要设计的两块】
A. 列表（点侧栏后）
- 宽度 240–320px（设计稿建议 280px），可滚动；在 900px 宽的面板里也不能挤坏详情。
- 每行必须能扫读：状态（颜色/形状/文字，不只靠颜色）、标题（最多 2 行）、类型、当前轮次/上限、更新时间（相对时间）、产物数量；stalled/failed 有明确警示，capped/reviewing 有“待处理”感。
- 选中态、悬停态、分组/筛选、空态、加载态都要给出。可用“需处理 / 进行中 / 已完成”分组或“全部/进行中/需处理”筛选，但不能假造数据。
- Research 和 Design 的列表共用结构，但要有轻量区分（图标、类型标签、产物标记；Design 可考虑封面缩略图，但不要为此牺牲扫读密度）。

B. 详情（点主题后）
- 顶部：标题（可两行）、状态、类型/通道/模型/轮次/更新时间、主题路径（可弱化/可复制），以及“下一步该做什么”的主操作。操作分三级：主操作（接受/恢复/继续等）、次操作（重新生成/请原会话判断/唤醒）、工具与危险操作（自检/登录/取消/撤回），不要把自检/登录放在第一层。
- 内容：按“第 N 版”分组的轮次；Research 用清晰的轮次表/时间线 + 本版总结（final.md）入口，Design 用每轮缩略图 + 全部图片画廊 + demo 预览 + 代码/文件。附件、回答查看、ZIP 下载、图片查看器、demo iframe 要有明确入口与层级。
- Research 的最终文档、Design 的图片/demo 是各自的第一眼重点；不要两者都做成同一张表。
- 覆盖：空主题、加载中、无产物、卡住（含原因）、失败、待接受、待原会话判断、已完成/已取消等状态；重新生成/继续一轮/人工核对的内联表单。
- 响应式：≥1200px 可用双栏（主内容 + 右侧产物/上下文栏）；900–1200px 收成单栏；<900px 列表可折叠/变成顶部选择器（给出规则即可）。

【设计方向（各出 1 张方向图）】
- 方向 A「紧凑控制台」：安静、密度高、接近开发工具；列表行有左侧状态条；详情顶部粘性标题 + 主操作，下面主内容 + 右侧产物/上下文栏。
- 方向 B「工作台」：列表按“需处理/进行中/已完成”分组；详情用“概览 / 轮次 / 产物”分段（或 tabs），减少滚动；Research 的轮次表更结构化，Design 的画廊更突出。
- 方向 C「档案/画廊」：Design 的列表可用封面缩略图，详情以画廊为主；Research 以文档/时间线为主；两者共享外壳但内容气质不同。注意不要变成博客或作品集网站。

三个方向都必须是可落地的桌面工具界面，不是营销页；要能看出列表与详情的真实信息层级，不要只画空壳。

【视觉语言】
- 跟随 DSH 现有中性 UI：浅色背景接近 #fff / #f7f7f8，深色接近 #1b1b1f；边框 1px 低对比灰；文字 12–13px，标题 15–18px；间距 4/8/12/16；圆角 6–10px，克制使用。
- Research 强调色建议蓝灰（如 #5b7cfa / #4f6fd8），Design 强调色建议暖琥珀（如 #d97706 / #c2761a）；状态色沿用：完成 #2e7d32、待接受 #6a1b9a、待判断 #3f7fbf、卡住 #ed6c02、失败 #c62828、取消 #757575。浅色/深色都要可读。
- 不要紫色渐变、巨大 hero、玻璃拟态、满屏胶囊标签、无意义插画。要像成熟的桌面工具：信息密度、对齐、层级、可扫描性优先。
- 中文界面；标题可能很长，给出两行截断/换行策略；不要依赖网络字体或外部图片。

【HTML demo 要求（关键交付）】
- 输出一个单文件 HTML（内联 CSS/JS，无 CDN、无外部图片/字体），可直接在 iframe 打开。
- 顶部或侧边提供切换：Research / Design、列表 / 详情、浅色 / 深色；默认展示 Research 列表 + 详情。
- 用真实示例数据（可用 ui-inventory.md 里的 dsh-pro website、dsh-pro 0.3.0 复核、dsh-pro 0.2.0 自审），列表至少 8–12 条，覆盖 completed/capped/reviewing/stalled/failed/cancelled/进行中；详情覆盖 Research 的轮次表 + final.md + 回答查看，Design 的图片画廊（用 CSS/SVG 占位图，不要外链）+ demo 预览 + 文件。
- 交互：点列表切换详情；搜索/筛选；展开/收起产物；打开图片/文本/demo 查看器；按钮点击有 toast 或状态变化即可（不需要真实后端）。列表和详情在 900px 与 1440px 两个宽度下都不能破版。
- 代码结构清晰，便于下一步改写成 React createElement；给出关键 CSS 变量和组件分区注释。

【方向图要求】
- 每张方向图 1722×997 左右（16:10 桌面），展示“列表 + 详情”的完整界面，并标注该方向下 Research / Design 的差异（可用同一张图里的两个小标签/两段内容，或一张主图 + 一个局部 inset）。
- 图中文字用中文，允许少量英文标签；不要出现大片不可读的乱码文字。重点展示信息层级与状态，不要画成手机 App。
- 三张图风格要有明显差异：A 密度/工具感，B 分段/工作台，C 画廊/档案感；但都必须能映射到同一套 panel.tsx 结构。

【额外要求】
- 请在回答里附一段“落地映射”：列表行/详情头的每个信息块对应哪个现有字段；主/次/危险操作分别对应哪些 action；哪些是纯视觉、哪些需要新增前端状态（如搜索/筛选）。不要新增后端接口。
- 如果同时能出 HTML，直接给完整单文件代码块。

## 出图数量

请生成 3 个可区分的设计方向，每个方向单独一张图；需要前端时给一个可运行的单文件 HTML demo。
