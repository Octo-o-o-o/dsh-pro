## 2. 为什么是 A「原生工作台」

第三轮的用户反馈是「更接近 DeepSeek Harness 的风格，但务必高级优雅」。A 是三个新方向里最直接回应这句话的：

1. **宿主一致性**：白底、浅灰工作区、细分隔线、极少量蓝色交互色，半径 12 / 20 / 28 分别对应按钮、内容卡、主面板。它看起来像 DSH 自己长出来的一页，而不是给插件另起一套品牌。
2. **先解释关系，再卖功能**：首屏右侧不是通用插画，而是一个「共享队列 + 回执」的工作区切片——队列里同时有 `chatgpt-pro-research` 和 `gpt-image-design`，回执显示第 03 轮、`answered`、本地产物目录。它把「两个插件共用一条网页会话」变成了可见的结构。
3. **克制的高级感**：靠留白、字号层级、面层关系和少量强调色，而不是渐变、玻璃、光球或假仪表盘。页面的「贵」来自排版纪律，不来自装饰。
4. **诚实**：回执卡明确写「回执示意 · 非实时」，状态旁写「已答复不等于已通过」，风险在首屏与页脚各出现一次。这比任何「AI 魔法」文案都更符合这个产品的实际边界。
5. **可转化**：安装区是整页唯一的高密度操作区，两条命令各自带复制按钮，登录调用给出两个入口，运行要求写清「DSH 保持打开，可最小化；不承诺关机后继续」。

## 3. 未被采纳的方向

| 方向 | 优点 | 不采用的原因 | 可复用场景 |
|---|---|---|---|
| 深夜实验台（round-02 image-02） | 开发者气质强，网格、刻度、等宽标签很「工具」 | 与 DSH 宿主风格距离最大；颜色和角标抢戏，容易像另一个产品 | 发布公告、终端风活动页 |
| 档案编辑部（round-02 image-01） | 辨识度最高，纸张、宋体、印章有记忆点 | 暖纸 + 衬线 + 红色印章是「研究档案」叙事，不是 DSH 原生界面；作为主站会让人误以为产品是文档工具 | 方法论文章、案例集、品牌周边 |
| 双通道（round-02 image-03） | 最直接解释「两个插件汇入一条通道」，轨道构图有冲击力 | 轨道成为页面主角，移动端要重排成纵向，信息密度反而下降；首屏容易被图形占满 | 「它怎么工作」独立页或架构图 |
| 插件手册（v2 B） | 目录 + 横向产品卡，开发者扫读效率高 | 更像参考文档，品牌展示感弱；首屏不适合承担「让访客理解产品」的任务 | `/docs` 入口或插件索引页 |
| 静夜模式（v2 C） | 深灰层次安静，适合夜间使用 | 首版只做一个主站，浅色原生工作台更贴近 DSH 默认界面；深色可作为后续主题 | 深色模式 / 夜间活动页 |

> 记录缺口：v2 的 B、C 只存在于原始答复中，没有落盘为可引用产物；本裁决只对已落盘的 A 与早期三方向负责。

## 5. 设计规范

### 5.1 颜色

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#FFFFFF` | 页面底色 |
| `--sidebar` | `#F9FAFB` | 工作区侧栏、队列 |
| `--group` | `#F5F6F7` | 标签、次级面层 |
| `--band` | `#F3F5F8` | 共用基础区、安装区的整段底色 |
| `--ink` | `#0F1115` | 主文字、主按钮 |
| `--muted` | `#61666B` | 次级文字（对白底 5.8:1，对 `--band` 5.31:1） |
| `--line` | `#DFE2E5` | 0.5px 内部分隔线、卡片描边 |
| `--line-strong` | `#D8DDE3` | 1px 分区边界、页眉/页脚边界 |
| `--blue` | `#285FCE` | 文本链接、`summary` 交互 |
| `--focus` | `#4176E6` | 键盘焦点环 |

没有渐变、没有半透明玻璃、没有彩色光晕。唯一的大面积「颜色」是浅灰面层和黑色主按钮；分区靠 `--band` 色带 + 1px `--line-strong` 边界，而不是装饰性图形。

### 5.2 字体与排版

- 正文：`system-ui, -apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`
- 等宽：`ui-monospace, SFMono-Regular, Consolas, "Liberation Mono", monospace`
- H1：桌面 60px / 1.21，移动 39px / 1.3；字距 `-0.025em`
- H2：36px（桌面）、28px（移动）
- 正文：16px / 1.75；次级 14px；代码 13px
- 字重：标题 600，按钮/标签 550，正文 400；不使用 800/900 的「喊叫式」标题
- 容器：`min(1216px, 100% - 80px)`；桌面段间距 74–90px

### 5.3 形状与层级

- 按钮圆角 12px，内容卡 20px，工作区面板 28px
- 内部仍用 0.5px 分隔线；分区边界与页眉/页脚用 1px `--line-strong`，配合 `--band` 色带，避免整页只有极浅的灰
- 首屏工作区是唯一有阴影的卡片：`0 12px 40px #15213712`，其余靠面层与边界
- 图标统一 1.6px 描边、24×24 viewBox、内联 SVG symbol

### 5.4 响应式

| 断点 | 变化 |
|---|---|
| `≤1150px` | 容器收窄，H1 48px，工作区侧栏 140px，安装/风险区间距缩小 |
| `≤900px` | 导航折叠为「菜单」；`nav-bar` 改为自适应高度，插件名不再挤在单行 |
| `≤850px` | 首屏单列，工作区最大 580px；产品卡仍双列；安装/风险改单列；步骤去掉左缩进 |
| `≤600px` | 工作区侧栏变顶部标签；产品/护栏/步骤单列；H1 39px |
| `≤320px` | 实测无横向溢出，但安装命令会换行，属于可读性下限 |

## 6. 关键文案

- 顶部导航：**ChatGPT Pro Research** / **GPT-Image Design** / 安装 / 风险
- 主标题：**用 ChatGPT Pro 跑多轮调研与设计。**
- 副标题：**在 DSH 里，两个插件共用一条真实网页会话。让 Pro 连续跑多轮调研与设计，产物保存在本地，需要人工处理时才提醒你。**
- 首屏标签：真实网页会话 / 无人值守 / 本地产物
- 首屏风险：**订阅网页自动化，不是官方 API。页面改版、账号风控及 ToS 风险由使用者承担；不绕过验证码 / 2FA。**
- 共用基础：**共用一条网页会话。** 两个插件共用浏览器 profile、执行队列、记录与安全护栏。
- 三步：**填写任务卡 → 无人值守执行 → 查看并裁决**
- 安装：**安装到 DSH。完成一次登录。**
- 边界：**先了解使用边界。** 不代表 OpenAI / ChatGPT 的官方产品或背书。

文案刻意避免：
- 「官方」「合作」「认证」等背书词；
- 「全自动」「无人监管」「永久免费」等过度承诺；
- 用户量、节省时间、成功率等没有证据的数字；
- 把 `final.md` 说成「最终交付物」——它是机械汇总，真正的裁决由宿主写。

### 7.1 实测记录

- 视口：1440×900、901×900、900×900、768×900、601×900、390×844、320×800。
- 横向溢出：全部为 0；390 宽下 `clientWidth=375`（桌面 Chromium 滚动条占 15px），`scrollWidth=375`。
- 导航：901 宽完整显示两个插件名且不溢出；900 宽折叠为「菜单」，展开后两个插件名换行到两行，无横向溢出。
- 分区：共用基础区与安装区底色 `#F3F5F8`，上下 1px `#D8DDE3` 边界；页眉/页脚 1px 边界；页脚底色 `#FAFBFC`。
- 外部资源：`performance.getEntriesByType('resource')` 仅一条 favicon 请求；无字体、图片、CSS、JS 外链。
- 控制台：1 个错误，仅 `favicon.ico` 404；无脚本异常。
- 对比度（白底/浅灰底）：
  - 次级正文 `#61666B` on `#FFFFFF` = 5.8:1
  - 次级正文 on `#F3F5F8` = 5.31:1
  - `answered` 状态 `#35533E` on `#EDF3EF` = 7.59:1
  - 主文字 `#0F1115` on `#FFFFFF` = 18.9:1
- 交互：
  - 复制按钮点击后 `#copy-status` 返回「已复制：dsh plugin --profile desktop add chatgpt-pro-research」；
  - 移动菜单展开后 `aria-expanded=true`，按 Esc 关闭并把焦点还给「菜单」按钮；
  - 安装锚点、跳过导航链接、`details` 展开均可用。
- 动效：`prefers-reduced-motion: reduce` 下 `scroll-behavior: auto`，按钮 transition 为 0s。
- 预览路径：`/gpt-image-design/asset?id=topic-ca9a&path=artifacts%2Fround-03%2Fcode-01.html` 返回 `text/html`，标题与正文正常渲染；设计面板的 iframe 使用同一路由。
- 同步：v1.1 修改后 `.html` 与 `.txt` 再次字节一致，SHA256 为 `CFA440CE0E5702BE833C3F578C1755FB6F9AC1077B4D3C48435D54D8AE7D970F`。

### 7.2 没有验证的部分

- Safari / Firefox、真实 iOS/Android 设备、屏幕阅读器、Windows 高对比度模式、200% 缩放；
- 设计面板 iframe 外层 `sandbox="allow-scripts"` 下的剪贴板行为（直接打开 asset 路由时复制正常，iframe 内可能触发降级提示）；
- 图片文件的实际导出尺寸：落盘为 1024×1536，原始答复声称已导出 1440×2160，但产物目录没有对应的 1440 文件；
- 页面在真实 DSH 宿主内的字体回退差异（Windows 与 macOS 的中文字重会略有不同）。

## 8. 遗留问题与落地建议

### 8.1 上线前应修

v1.1 已修：顶部导航改为两个插件名；「上夜班」「一条通道」「交代任务」等比喻改为直白说明；共用基础区/安装区改用 `#F3F5F8` 色带并加 1px 边界；产品卡「final.md 保留最终汇总」改为「汇总本轮记录」。

仍需处理：

1. **移动端命令换行**：390/320 宽下 `chatgpt-pro-research` 会在连字符处断行。建议给 `pre` 加横向滚动（`overflow-x:auto; white-space:pre`）或把命令拆成「命令 + 包名」两行。
2. **favicon 404**：加一个内联 SVG favicon，顺手消掉唯一的控制台错误。
3. **分享元信息**：补 `og:title`、`og:description`、`og:image`、`twitter:card`、`theme-color`；OG 图可用首屏工作区切片，不必另做插画。
4. **文档入口**：导航现在只有 GitHub，建议加「文档」指向 README / `docs/usage.md`，否则访客看完首页仍不知道设置项和故障排查在哪。

### 8.2 可以下一版再做

- 深色主题（复用「静夜模式」的层次，不沿用双通道的高饱和色）；
- 英文版或中英切换；
- 真实 DSH 面板截图（需脱敏、固定版本，避免截图与当前 UI 漂移）；
- 「它怎么工作」独立页，把双通道的轨道图收进去；
- 用真实产物做 OG 图与社交分享卡片。

### 8.3 实施边界

本文件只裁决设计与 demo，**没有改仓库其它代码、没有 push、没有部署**。若要正式上线，建议单独开一次实施：

- 方案一：`site/index.html` 单文件 + GitHub Pages workflow；改动最小，和当前 demo 一致。
- 方案二：把页面拆成 `site/` 下的 HTML/CSS/JS，接构建与预览；适合后续加文档、博客、英文版。
- 方案三：只把 demo 作为 `docs/design/dsh-pro-website/` 的设计记录，官网另做；适合还想再改一版视觉的情况。

无论哪种，都需要先确认：部署域名 / 仓库 Pages 设置、是否保留「非官方 API」风险声明在首屏、是否加文档入口。

## 9. 结论

A「原生工作台」是这三个方向里最像 DSH、也最适合做主站的一版：它没有把插件包装成另一个品牌，而是把「共享队列、回执、本地产物、人工裁决」这些真正的产品结构放到了首屏。视觉上克制，信息上诚实，安装路径短。

v1.1 之后，导航直接写插件名，正文不再用「上夜班/一条通道」这类比喻，共用基础区与安装区有了更明确的色带和 1px 边界。当前 demo 已经可以作为官网的视觉与内容基线；上线前主要剩移动端命令换行、favicon、分享元信息与文档入口四件小事。
