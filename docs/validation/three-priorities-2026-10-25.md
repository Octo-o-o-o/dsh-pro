# 三项最小改动与本机客户端验证

2026-10-25。本轮只实施产品评审收敛的三项，以及用户追加的响应式展示修整。代码保留在 monorepo 工作区；没有修改两个生成分发仓库，没有提交、推送或发布，也没有提升版本。

## 实现范围

1. **可信的完成判定。** 引擎对照原成功判据检查完成声明：项目数量和名称一致、无重复、全部满足且有依据。矛盾结果重试一次，仍不合法则进入既有待判断状态，保留回答，不额外发研究或生图请求。合法的未完成结果继续遵守原预算。Design 文本通过后停止等待视觉确认。人工接受用独立的 `acceptedAt` 记录，续轮或重做时清除；唤醒不再把模型的停止理由当作人工验收。
2. **Research 交付稿覆盖范围。** `report.md` 首行使用 `<!-- dsh-pro-report: {"generation":1,"throughRound":2} -->` 声明来源。面板显示已覆盖当前轮次、交付稿待更新或覆盖范围未确认，并提供来源回答/裁决入口。文件内容摘要驱动刷新，不依赖主题更新时间。没有新增报告生成调用或版本管理系统。
3. **Design 选图继续修改。** 图片卡复用续轮弹窗，显示所选底图，填写保留与修改要求；默认且限定为一轮一个结果。记录底图关联，旧图保留。项目和本机存储均校验产物归属、真实路径、图片签名并校验暂存副本摘要。实际请求只带所选底图，恢复会话失败也不回退全部历史图片。关闭 edits 或接口拒绝 edits 时停止；未添加画布、遮罩或自动视觉评分。

## 自动化检查

最终运行：`npm test` → **153 passed / 2 skipped**；`npm run typecheck`、`npm run build`、`node scripts/smoke-bundle.mjs` 均通过。两插件仍各注册 1 个工具、9 条路由、2 个客户端插槽。`git diff --check` 没有空白错误。

针对性覆盖：

- 缺项、重复、名称不匹配、partial、unknown、无依据、结论矛盾均不能自动完成；原始回答保留且只提交一次，仍可人工接受。
- Design 文本通过不等于视觉通过；显式底图修改即使重试既有失败轮次也只有一个结果、一轮。
- 唤醒自动完成任务不会断言用户已接受，即便模型停止理由恰好写着“人工接受结果”；显式接受会记录并正确唤醒，续轮清除旧接受记录。
- 交付稿从旧格式到有归属、续轮、重做、错误归属、文件早于答复及正文原地更新。
- 本地 HTTP 模拟 API 在项目/本机两种存储下，三张图选第二张，捕获到的 multipart 仅包含第二张的字节；一条经过面板 POST 路由，另一条经过工具入口。旧图未覆盖，底图关联保留，重新加载服务不重发。非法/非本主题路径、目录联接越界、伪图片、关闭编辑均被拒；edits 返回 404 后没有 generations 回退。

默认跳过的两项是现有可选 Chrome 传输 fixture 测试。本轮没有真实 ChatGPT 提交或收费生图，不声称验证了线上模型生成质量。

## 本机 DSH 客户端实测

使用本机安装的 **DeepSeek Harness.exe**。desktop profile 两个插件均通过 junction 指向本 monorepo 的 `packages/research`、`packages/design`；本地构建直接用于客户端验证。

通过原生窗口操作检查约 520、600、640、900、1280、2560 像素宽的窗口；展开宿主侧栏后，另外检查约 **240、326 像素**的实际插件可用宽度。短窗口检查到客户端允许的约 **520 × 600**。测试为当前浅色主题，不外推为所有设备、DPI 或主题均已实测。

覆盖的展示数据包括：无匹配搜索、零轮次/零产物、正常和未知来源旧稿、后续证据已加入的旧稿、原地更新报告、超长路径和代码、超长标题、24 轮记录、横图/竖图/方图及加载失败图片。

观察后修整：

- 详情长标题最多三行，完整标题仍保留在提示和可访问名称中；小于 400 像素可用宽度时收紧留白和字号。
- 轮次表保持可读列宽和完整裁决文字，表格内部横向滚动；提供提示和可键盘聚焦的区域。已实测滚至右侧，回答/裁决按钮完整可见。
- 短窗口中弹窗正文可滚动，标题、反馈和底部操作保持可达。底图弹窗明确显示 image-02、缩略图、一轮一个结果以及“提交修改”。坏图保留重试并禁用修改入口。
- 修复了本轮接入时普通续轮按钮将点击事件误传为底图参数的问题；普通续轮的主/次入口、定向修改、空输入校验、Escape 关闭及关闭后的焦点恢复均已复测。
- “已达到轮次上限”改为更准确的“结果待接受”，避免提前停止或文本通过时误导用户。
- 对齐轮次列表的 `judgeError` 字段与后端记录；已在客户端验证矛盾裁决显示“裁决失败”，并能打开保留下来的 `02-verdict.md` 错误说明。

关键真实客户端观察：修改报告正文及覆盖头而不修改 `topic.updated`，轮询后自动显示新正文和“覆盖至第 2 轮”；来源回答可正常打开。定向修改弹窗选择第二张图时，预览和文件名一致。没有在真实客户端提交模型任务。
