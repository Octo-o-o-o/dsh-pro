## 任务

背景：这是一个 DSH（DeepSeek Harness）插件仓库，包含两个 npm 包：chatgpt-pro-research（用 ChatGPT Pro 网页做无人值守多轮调研）和 gpt-image-design（用同一个网页会话生成设计图与 HTML demo）。两者复用同一套 core 引擎、transport（Playwright 驱动 chatgpt.com）和侧边栏面板。当前版本 0.2.0，单测与类型检查通过，README 已承认部分未覆盖项。

任务：把附件里的源码和设计文档当成一个真实产品来审。源码是事实来源；设计文档里的承诺要逐条对照代码，指出哪些没实现、哪些实现得不对、哪些应该从文档里撤回。你无法运行代码，所以请基于代码路径推理，并对不确定的地方明确标注“需要实测”，不要臆造 API 或 DSH 能力。

本地已看到、需要你验证或反驳的三条假设（不要只重复，要给出代码依据和更细的修法）：
1) 重启后恢复断链：submissionId 只存在 transport 内存 map，重启后 poll 返回 unknown，engine 转 stalled(ui)；human_check=submitted 也只是转 waiting 再 poll，仍然 unknown；unknown_submission 这个 stall reason 代码里从未产生。
2) 两个插件共享同一个 Chrome profile 目录，但各自 launchPersistentContext；同一插件的不同 cwd 也各有 engine 队列、共用一个 transport，单队列/单浏览器并不成立。
3) 材料安全：secretGlobs 没有接入 buildManifest；材料路径没有禁 .. 和绝对路径；project store 的 manifest 写入绝对路径。

请至少覆盖 7 个维度：
- 重启/崩溃后的恢复语义（reattach、回执、unknown_submission、人工核对）
- 并发与多实例（两个插件、多个 cwd、多个 DSH 窗口、同一 profile 的锁与队列）
- 传输鲁棒性（发送成功判定、上一轮答复误判、流式完成、错误/限额/验证码/重试、页面改版、图片/代码抓取范围）
- 材料与安全（密钥扫描、路径穿越、绝对路径、二进制、大小限制、公开仓库）
- 记录与审计（atomic 写、事件流、receipt 哈希、final 覆盖、nextBrief 丢失、registry 竞态/迁移）
- 面板 UX（继续/登录/自检/查看原文与 final、项目分组、筛选搜索、轮询、a11y、设计画廊）
- 发布与文档一致性（设计文档承诺 vs 代码、0.1→0.2 迁移、双包版本锁步、CI/真实浏览器测试）
