# dsh-pro 0.3.0 复核：从裁决到可实施补丁

## 研究问题

在当前 0.3.0 工作区（含 dispatch 补丁、API 通道、reviewing 状态）上，上一轮裁决是否仍是最优建议？哪些应保留、降级、删除或补漏？请给出可直接实施的 P0/P1 顺序与验收断言。

## 成功判据

- 逐条复核 adjudication.md 中的 P0/P1，给出保留/降级/删除/补漏，并引用当前文件或可复现行为。
- 至少 10 条针对 0.3.0 的具体结论，其中至少 2 条是旧审计未覆盖的新问题；不重复已修复项。
- 复核 dispatch 补丁：覆盖崩溃窗口、reattach/continue/human_check 交互和 API 通道，至少指出一个剩余漏洞或明确证明没有。
- 给 P0-2 本轮消息锚点与 P0-3 材料快照的最优实现方案（改动点、字段/状态、失败语义）及最小验收断言，并说明先后顺序。
- 给 2 周内按投入/收益排序的行动计划，明确哪些建议应撤回或后置。
- 结论先行，中文，表格或分级列表；所有判断引用当前行号或行为，无法确认处标注“需实测”。

## 任务

这是同一项目的 0.3.0 复核子主题，不是重复 0.2.0 的审查。

背景：上一轮 0.2.0 自审已经结束，宿主的裁决在 materials/adjudication.md（会作为本轮材料）。之后仓库前进到 0.3.0：新增 OpenAI 兼容生图 API 通道、reviewing 交接状态、多版本/产物、面板查看器、共享 transport；并且刚加了 P0-1 的 dispatch 意图补丁（RoundRecord.dispatch，提交前落盘，未观察时拒绝 resume/continue/submitRound 自动重发）。旧 0.2.0 记录仍在 docs/research/dsh-pro-0-2-0/，不要要求重发旧材料。

你的任务不是同意宿主的裁决，而是完整复核它是否仍是最优建议：
- 逐条判断 adjudication.md 里的 P0/P1 是保留、降级、删除还是补漏；如果排序错了，直接给新排序。
- 以本轮附件中的当前源码为事实来源；旧版已修项不要重复。
- 特别复核 dispatch 补丁：落盘时机、崩溃窗口、与 reattach/continue/human_check 的交互、API 通道行为；指出剩余漏洞，或明确证明没有。
- 对 P0-2（本轮消息锚点）和 P0-3（材料快照/最终正文扫描）给最优实现方案：改动点、字段/状态、失败语义、最小验收断言；说明为什么这个顺序最优。
- 检查旧审计可能漏掉的新代码：API 通道的 key/HTTP/下载边界、reviewing 状态的恢复与面板、面板动作与当前 detail 的竞态、跨进程 profile 所有权、损坏记录、事件/回执审计。
- 你无法运行代码/浏览器；无法确认的地方明确写“需实测”，不要臆造 DSH API。
