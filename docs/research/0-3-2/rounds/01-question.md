# 两个插件的小而美产品补强评审（0.3.2 之后）

## 研究问题

在保持单账号、单会话、不铺开新功能的前提下，Pro Research 与 Image Design 在 0.3.2 之后最值得继续投入的 3–6 件事是什么，如何同时提升专业度与吸引力？

## 成功判据

- 给出不超过 6 条改进建议，按用户价值/实现成本排序，每条指向现有能力或已知缺口，并标注「加深」还是「铺开」
- 专业度与吸引力两类各不少于 2 条，每条给出可验证的验收信号（指标、用户可见结果或测试方式）
- 指出最影响「安装→第一次成功」的 1–2 个摩擦点，并给出 1 天内可完成的最小改动
- 明确列出 2–3 项应当不做或砍掉的事，防止功能铺开
- 对两个插件分别给出结论，并回答共享核心该继续共享还是某项改进只落在一个插件上
- 给出一句差异化定位（对比 ChatGPT 官方 Deep Research 与 browser-use 类工具），且不建议多账号、多 provider、通用聊天 UI 等非目标

## 任务

你是一位同时懂开发者工具产品、浏览器自动化可靠性和开源插件分发的评审者。我是这两个 DSH 插件的作者，想要一份不留情面的外部产品评审，不是夸奖。

## 背景
- 两个插件：chatgpt-pro-research（用 ChatGPT Pro 网页做无人值守多轮调研）和 gpt-image-design（同一网页会话或 OpenAI 兼容生图 API 出设计图 + 单文件 HTML demo）。
- 共用一套 core（状态机/记录/材料/产物）、transport（Playwright 驱动 chatgpt.com + OpenAI images 客户端）、一个 Chrome profile、一个共享的侧边栏面板工厂。
- 当前源码 0.3.2：已修过一轮可靠性（恢复/裁决/删除/并发串行/CSP/zip 炸弹等），面板做过一次主从结构精修；124 测试通过。但 0.3.2 尚未 sync 到两个公开分发仓库，市场条目还停在 0.3.0/0.3.1（见 docs/marketplace.md）。
- 真实网页只验证过登录、单轮、附件、同会话两轮、图片抓取；真实 API 生图只用本地假服务验证过；页面改版/风控/超长回答/断线恢复未验收。
- 明确的非目标：不做多账号/多 profile 扇出、不做多 provider 路由、不做通用聊天 UI、不做验证码绕过、不自动 push。

## 我的约束（很重要）
- 我要的是**小而美**：把现有两条链路做到极致，而不是加新赛道。任何建议都必须能回答「这是加深还是铺开」。
- 单个改进最好能在一个版本内交付；需要大改架构的建议请标注代价。
- 不要建议「做个 Web 版控制台」「支持 10 个模型」这类扩张型功能。

## 我希望你回答
1. 站在一个准备安装的 DSH 用户角度：从看到市场条目/README，到第一次成功产出，最大的摩擦在哪？哪些是「还没试就关掉」的原因？
2. 专业度：现在最像「玩具」而不是「工具」的地方是什么？可靠性、证据链、错误处理、兼容性、升级/迁移，哪些还欠火候？
3. 吸引力：这两个插件各自最值得被展示的「哇点」是什么？现在 README/面板/默认设置有没有把它埋掉了？
4. 给出不超过 6 条改进建议，按价值/成本排序；每条写清：解决什么问题、改哪里、验收信号、是加深还是铺开。
5. 明确 2–3 项应当不做或砍掉的事。
6. 两个插件分别给结论：共享核心该继续共享吗？哪些改进只该落在一个插件上？
7. 一句话差异化定位（对比 ChatGPT 官方 Deep Research、以及 browser-use 类自动化工具）。

## 注意事项
- 你只能看到我给的文档，不能假设代码里有文档没写的功能；如果文档之间互相矛盾，指出来。
- 文档里的「已验证」有明确边界，不要把作者的自述当成独立验收。
- 如果你认为某个我视为优势的设计其实是负担（例如 9 条路由、15 个 action、单会话复用），直接说。
- 输出用中文，结构化（标题 + 表格/清单），不要空话。
