## Research 子任务：research_priorities

建议顺序：完成可信 → 交付稿覆盖当前证据 → 选中一张图继续改。

独立核实的关键点：

1. 材料扫描/快照、增量清单、逐条判据、裁决失败交接、report 入口、续轮材料均已存在，不应重新当新增。
2. `parseJudge` 未用 criteria 约束 done，engine 直接依据 done 完成；judge 是本轮最多 30,000 字符的文本输入，没有图片。
3. `wake` 只要求 completed，却复用“用户已接受”的通知；自动完成也可能被误写成人工验收。
4. report 仅存在性检测，旧版提示排除 report；续轮/重做无报告归属记录，旧稿可能继续被优先展示。
5. 来源回查只需要固定轮号与现有回答/裁决入口；不应扩大成通用引用系统或把全部历史塞进每次 judge。

主宿主裁决：上述代码事实经再读相关函数确认，采纳。关于旧 report 的真实用户发生频率保持未知，报告明确标成静态推断。采用极小的版本/轮次来源记录，而非引入报告平台。其提议“旧版稿仍可找回”收窄为保留已有旧稿可读；不在本轮额外承诺一整套报告历史版本管理。

## Design 子任务：design_priorities

独立初始排序：选定底图定向修改 → Research 报告新鲜度 → 一条候选版真实首跑/续轮/中断恢复验证。

独立核实：图片卡只有查看；普通 continue 已有保留措辞与材料路径，因此真正新增的是明确绑定被选中的产物；API 参考图来自本轮 request.files；多方向生成提示要求方向互异，微调入口宜默认 1 张；report 的存在性优先及依赖 topic.updated 刷新不足以表达文件更新与覆盖范围。

主宿主提供当前原函数的内存复现后，Design 子任务再次读取 parser 和 engine，确认 criteria 被解析但没有参与 done，改为把完成一致性提升至首位；同时保留“Design 体验可排第二”的价值判断。

主宿主裁决：采纳明确底图、复用 continue、默认 1 张、保持旧图及来源关系。Design 最终答复明确反对把并排对照塞进首版；采纳这个收窄，改用现有查看器依次回看，不新增对照面板。通道不支持 edits 或显式关闭时不得静默无底图生成。将真实闭环验证作为三项共同交付条件，不占第四项、不重启完整矩阵。执行顺序选共同可信约束 → Research 报告 → Design 微调；两个插件的第 2/3 项可在第 1 项明确后分别推进，顺序不代表 Design 价值低。

## 统一收敛

| 候选 | 裁决 | 理由 |
|---|---|---|
| 完成判定与逐条判据一致 | 采纳，第一项 | 确定代码缺口，并有原函数实际复现，影响两插件信任 |
| report 覆盖版本/轮次与更新可见 | 采纳，第二项 | 补证据之后仍能正确识别当前结论，增量边界小 |
| Design 选中图直接续改 | 采纳，第三项 | 把已有参考图能力连到画廊，明显减少用户操作成本 |
| 专用并排对照界面 | 后置 | 接受 Design 子任务的范围收窄；来源关系加现有查看器足以验证首版 |
| 关键结论引用全部可点击 | 部分采纳 | 只复用固定轮次回答/裁决入口，保持 HTML/危险 URI 惰性 |
| 自动视觉判断 | 不采纳 | 超出文本裁决证据，新增模型与质量承诺会扩大范围 |
| 采用版本/产物的新状态 | 后置 | 现有 accept 已存在，先做报告归属和底图绑定 |
| 精美 HTML 导出 | 后置 | 当前 ZIP、本地文件/demo 已可使用，先解决内容正确归属 |
| 独立的大规模首跑/恢复工程 | 部分采纳 | 必要真实链路收进三项交付条件，避免把十项工作包进三项 |
